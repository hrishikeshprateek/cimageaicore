# Video Composer

Turns an **analysed** review/testimonial video into a branded short: the clip sits inside the college
frame (top/bottom layers), with burned-in captions and a lower-third, exported for Reels/Shorts (1080×1920),
feed (1080×1080) and YouTube (1920×1080). Rules (or Gemini) propose the cut; a person previews, nudges and
renders; ffmpeg does the work. Renders stay in `data/renders/` — publishing goes through the approval gate.

```
job blocks ──► cuts.py (quotes + key moments + transcript → 2-3 windows, lower-third from person blocks)
                 │  optional: Gemini refinement, prompts/video-composer/cuts_v1.md (structured JSON)
                 ▼
web/composer.html ── pick job → cut → nudge in/out → edit cues → Render
                 ▼
POST /api/v1/jobs/{id}/compose ──► renders table (QUEUED) ──► RenderWorker (daemon thread)
                 ▼
renderer.py: -ss/-t cut → scale into video_zone → overlay layers → caption PNGs (enable=gte*lt) → lower-third → x264/aac
```

## Switch it on

```
COMPOSER_ENABLED=true        # default false
COMPOSER_TEMPLATE=placeholder
```
All keys are `COMPOSER_*` in `.env` (see `.env.example`) and live in `services/video_composer/settings.py`;
nothing in `apps/api/config.py` changes. Open **http://localhost:8000/composer**.

## Template = one directory

`data/composer/templates/<name>/template.json` + the layer files it references. The `placeholder` template is
generated by `placeholder.py` the first time it is needed and mirrors the real CIMAGE 9:16 frame:
**top band 0–415 px, clip window 415–1385 px, bottom band 1385–1920 px**, navy `#0d2c5e` / gold `#f5c542`.

```jsonc
{
  "name": "cimage",
  "brand": {"name": "CIMAGE Group of Institutions", "primary": "#0d2c5e", "accent": "#f5c542"},
  "caption": {"font_size": 54, "colour": "#ffffff", "box_colour": "#000000", "box_opacity": 0.6, "max_lines": 2},
  "lower_third": {"name_size": 42, "role_size": 28, "bg_colour": "#0d2c5e", "accent_colour": "#f5c542", "start": 0.6, "end": 6.0},
  "font_regular": null,               // relative path inside the template dir; null = COMPOSER_FONT_REGULAR / bundled Poppins
  "layouts": {
    "reels": {
      "width": 1080, "height": 1920,
      "video_zone": {"x": 0, "y": 440, "w": 1080, "h": 920},   // the clip is fitted (contain) inside this, aligned top
      "video_align": "top", "fit": "contain", "background": "#0d2c5e",
      "layers": [ {"name": "frame", "file": "reels_frame.png", "x": 0, "y": 0, "z": 0} ],   // PNG alpha / .mov ProRes 4444 / .webm VP9 alpha
      "caption_zone": null,            // null = below the clip when there is room, otherwise over its bottom edge
      "safe_area": {"x": 60, "y": 250, "w": 860, "h": 1350}   // keeps captions out of the Reels UI rail
    },
    "square": { ... 1080x1080 ... }, "landscape": { ... 1920x1080 ... }
  }
}
```

**Slotting the real assets in is config only:**
- UI: *Template → Upload a real layer* — name `cimage`, preset `reels`, layer `frame`, tick *replace all*, choose the
  PNG with a transparent middle. The template is created from the placeholder geometry (other presets keep the
  placeholder layers until you upload theirs). Then pick `cimage` in the dropdown or set `COMPOSER_TEMPLATE=cimage`.
- Or copy `data/composer/templates/placeholder/` to `.../cimage/`, replace the PNGs, edit `template.json`.
- Brand fonts: `COMPOSER_FONT_REGULAR/BOLD` (or per template). Text is drawn per script run — a Latin-only brand
  font still gets Devanagari from the bundled Noto Sans Devanagari fallback.
- Animated layers: `.mov` ProRes 4444 or `.webm` VP9 with alpha, looped over the cut (`"loop": true`).
- `GET /api/v1/composer/templates/{name}/preview?preset=reels&aspect=9:16` renders a still of any layout for checking.

## Captions and Devanagari

Transcript segments (30–60 s speaker turns, second-resolution timestamps) are split at sentence ends / word
boundaries into ≤ 2 × 34-character cues, timed in proportion to their length, clipped to the cut. Every render also
writes `.srt` and `.ass` sidecars next to the MP4 (upload them as platform captions).

Captions are burned as **alpha PNG overlays rendered with Pillow** (`textrender.py`), not `drawtext`/libass: the
dev machine's Homebrew ffmpeg has neither, and PNG overlays behave identically on every ffmpeg build.
Devanagari needs a shaping engine (matras, conjuncts): Pillow uses libraqm when **FriBiDi** is loadable.
- Linux/Docker: `libfribidi0` is installed in `docker/api.Dockerfile` — shaping works in-process.
- macOS (Apple silicon): Homebrew's FriBiDi is in `/opt/homebrew/lib`, which Pillow's bundled raqm does not
  search; the composer detects this and renders text in a child interpreter with `DYLD_FALLBACK_LIBRARY_PATH` set.
  Alternatively start the API with `DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib uvicorn …`.
- `GET /api/v1/composer/system` → `text_shaping` reports which path is active; each render records `detail.text_shaping`
  (False = complex text was drawn without shaping — treat the output as wrong).
- `COMPOSER_CAPTION_ENGINE=libass` switches to ffmpeg's `subtitles` filter (needs an ffmpeg built with libass).

## Cut selection

`cuts.py`, deterministic, offline:
1. every **quote** → window snapped to the estimated start of its sentence and to the end of the speaker turn;
   score = 1.0 + key-moment importance inside (+0.1…0.5) + named speaker (+0.2) + length near target (+0.2) + quotable length (+0.1)
2. every **key moment** → window from its sentence start, ~60 % of the target length (score 0.6 + importance)
3. fallback: longest transcript turns, then the opening of the video
4. overlapping windows (> 50 % of the shorter) are dropped, best `COMPOSER_MAX_CUTS` kept, all within `COMPOSER_MIN/MAX_CUT_SECONDS`.
Lower-third = the person block matching the quote's speaker (or whoever is on screen in the window); unnamed
speakers get none — the UI lets you type one. `GET …/cuts?refine=true` (or `COMPOSER_CUTS_REFINE=auto`) sends the blocks
and these proposals to Gemini through the gateway's `generate_structured()` with `prompts/video-composer/cuts_v1.md`
and falls back to the rule-based list with a warning on any failure (the mock provider always falls back).

## API

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/api/v1/composer/system` | enabled flag, ffmpeg capabilities, text shaping, templates, presets |
| `GET/PUT` | `/api/v1/composer/templates[/{name}]` | list / read / replace `template.json` |
| `GET` | `/api/v1/composer/templates/{name}/preview?preset=&aspect=` | still preview PNG |
| `POST/DELETE` | `/api/v1/composer/templates/{name}/layers` | upload (multipart `file`, `preset`, `layer`, `x`, `y`, `z`, `replace_all`) / remove a layer |
| `GET` | `/api/v1/jobs/{id}/cuts?refine=` | proposed cuts with cues + lower-third |
| `GET` | `/api/v1/jobs/{id}/captions?cut_in=&cut_out=` | cues regenerated for a nudged window |
| `GET` | `/api/v1/jobs/{id}/media` | source file stream for the trim preview |
| `POST` | `/api/v1/jobs/{id}/compose` | `{cut_in, cut_out, presets[], template?, captions?, captions_enabled, lower_third?, fit?, title?, cut_id?}` → `202 {renders[]}` |
| `GET` | `/api/v1/renders?job_id=` · `/api/v1/renders/{id}` | records (`QUEUED → RENDERING → DONE / FAILED`) |
| `GET` | `/api/v1/renders/{id}/video` (Range OK, `?download=true`) · `/captions.srt` | outputs |
| `DELETE` | `/api/v1/renders/{id}` | remove record + files |

Records live in the `renders` table (`database/migrations/010_composer.sql`, audit rows `render.*`) or, without
PostgreSQL, in `data/renders/records/*.json`. Outputs: `data/renders/<job_id>/<render_id>_<preset>.mp4` (+ `.srt`, `.ass`).
Renders interrupted by a restart are marked FAILED at the next start.

## Export

H.264 high 4.1, `COMPOSER_X264_PRESET` / `COMPOSER_CRF` (default medium / 20), 30 fps, yuv420p, `+faststart`;
AAC 160 kb/s 48 kHz stereo with 0.15 s fades; silent sources render without audio. A 30 s reel takes ≈ 3–5 s on the
MacBook at `fast`. The exact ffmpeg command is stored with each render (`ffmpeg_command`).
